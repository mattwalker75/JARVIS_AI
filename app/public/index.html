    Configuration

    Everything in JARVIS_CONFIG.json + JARVIS_SECRETS.json. Edit the friendly fields or the raw JSON — they stay in sync. Saving applies changes live (the app re-reads them on your next message) — no restart for ordinary settings like endpoint / model / tiers / params / prompts.
    Model & LLM
    Configure local model with JARVIS_LOCAL_LLM.sh script ( run "JARVIS_LOCAL_LLM.sh config" for full help guide )
    Cloud models (GPT‑4o/4.1, Claude, Gemini) are multimodal and strong across the board — use single, one model handles chat and vision. Multi (chat / cheap / smart / vision) is mainly for local setups that stitch together specialized models (e.g. a text model + a separate vision model). You can still use multi on cloud purely to route tiers by cost.
    Pick a provider to fill the endpoint URL, add its API key, then List models to populate the pickers. Each tier groups its best-fit models on top (vision models in the vision tier, etc.) — but you can pick any model in any tier, or ✎ Custom… to type your own. “Generic” points at any OpenAI-compatible URL.
    📖 Use MODELS.md (in the project root) as a reference when selecting a model — it lists which models fit the chat / cheap / smart / vision tiers. Edit it (and app/public/models.json) to keep the list current.
    MLX models local · Apple Silicon
    namemodel (mlx-community/…)port
    Each entry runs its own mlx_lm.server on its port (models from mlx-community on Hugging Face, cached in mlx/models/). Saving writes the config, but the UI can't start host processes — run ./JARVIS_LOCAL_LLM.sh start --backend mlx afterward to (re)launch. Full guide: ./JARVIS_LOCAL_LLM.sh config --backend mlx.
    Prompts applies live
    The active prompt = Prompts/default_master.prompt + default_system.prompt. Sent to the model as master → system → built-in tool/planner/coding rules (rules always appended). Save as active applies on the next turn (no reload). Save as… / Load use named sets Prompts/<name>_master.prompt + <name>_system.prompt — editable outside the app.
    Behavior applies live
    Turn the watchdog OFF (🐕 in the header) for long coding tasks so slow local generations aren’t killed. Plan mode (🗺) makes JARVIS clarify + plan before executing.
    Ollama host · needs --reload
    Context is pre-allocated at load (bigger = more RAM + slower first load, fixed ceiling). keep_alive -1 avoids ~minute cold reloads.
